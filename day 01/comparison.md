# День 1. Правила Bookreader — две генерации

Один промпт, без уточнений. Текст: `prompt.txt`.

Каркас и правила v2 лежат в `bookreader/`. Здесь снимки и диффы, без ключей.

## Промпт

Добавить фильтр библиотеки по строке (автор или название): query на `GET /books`, поле на `LibraryPage`, тест. Следовать правилам проекта.

## Что проверяли

`scripts/check.sh`: `tsc`, тесты API, ESLint (`no-explicit-any`, `no-console`).

## Генерация 1 (правила v1)

Проверка прошла. Ассистент добавил `GET /books?q=`, поле поиска и тест.

Два промаха относительно того, как должен выглядеть результат:

- Фильтр шёл через `LIKE` по колонке `authors` (JSON-строка), а не по разобранным именам.
- У поля поиска был только placeholder, без видимого `<label>`.

Дифф к каркасу: `generation-1-apps.diff`.

## Что изменили в правилах (v2)

- `q` сравнивает title и каждого автора после `JSON.parse`, без учёта регистра. Нельзя `LIKE` JSON-колонку authors.
- У поля поиска на `LibraryPage` есть видимый `<label>`.

Дифф правил: `rules-v1-to-v2.diff`. Снимок v2: `rules-v2.md`.

## Генерация 2 (правила v2)

Тот же промпт на чистой копии. Проверка прошла. `scripts/check.sh` не менялся.

Фильтр в памяти по title и `authors[]`. На странице есть `<label htmlFor="library-search">`.

Дифф: `generation-2-apps.diff`.

## Что сильнее всего сдвинуло качество

1. Явный запрет `LIKE` по JSON авторов. Пока в правилах было только «фильтр на GET /books», ассистент честно сделал SQL LIKE по колонке.
2. Требование видимого `<label>`. Placeholder не заменяет подпись.

Остальное v1 уже держал: маршрут, `Library.list`, тест через `inject`, без `any` и `console.log`.
