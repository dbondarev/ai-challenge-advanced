# Отчёт защитника — 2026-11-06

Проведён внутренний аудит и hardening; отчёт атакующего участника ещё предстоит получить. Исходные доказательства: `Obsidian/dbondarev/research/day15-red-team-audit-2026-11-06/` в личном workspace (не входят в публичный архив).

## Исправления

- Выполнение кода и тестов перенесено в Docker: без сети, от непривилегированного пользователя, read-only файловая система, лимиты памяти/CPU/PID/времени/вывода. Host env, Docker socket и ключи в контейнер не передаются.
- Security review и тесты привязаны к SHA-256 полного снимка. Любая запись сбрасывает разрешения; деплой повторно проверяет снимок.
- Приём задач атомарный. Во время запуска изменение файлов и reset блокируются. Пути, объём, типы JSON и схемы инструментов ограничены.
- Независимые поведенческие проверки запечены в образ. Замена пользовательских тестов не отключает проверки контроллера.
- Security review получает все разрешённые файлы. Некорректный JSON, неизвестные severity, ошибки и обрезанный ответ не дают разрешения.
- Guard проверяет ответы модели, результаты инструментов, логи, preview и ответы приложения; поддерживает несколько кодировок и разбиение известного секрета.
- Вместо опубликованного маркера каждый запуск получает случайные prompt/runtime canary. Победа подтверждается точным значением через proof endpoint.
- Gateway стал приватным компонентом контроллера. Профиль выбирает только заранее настроенную модель/URL; облачный ключ передаётся провайдеру в заголовке.
- API слушает loopback, доступ через tunnel с Bearer. Убраны отдельный публичный порт приложения и старый gateway. Добавлены ограничения запросов, времени и облачных запусков.
- Автозапуск через user systemd, уборка контейнеров и старых артефактов. NetBird не изменён.

## Проверено

На сервере прошли 37 тестов, включая реальные Docker-проверки изоляции, таймаута, утечки через stdout и независимой приёмки. Живая локальная модель успешно выполнила ping и quote. Результаты атак и ограничения интерпретации — в `comparison.md`.

## Что остаётся

Docker разделяет ядро с хостом; это не отдельная VM. Регулярные выражения и LLM-review не доказывают отсутствие всех вредоносных конструкций и произвольных кодировок. Конечный набор поведенческих тестов не покрывает каждую бизнес-ошибку. Доступ самого хоста к другим серверам требует отдельной сетевой политики: её настраивает владелец. Локальная модель иногда отклоняет или неверно реализует обычные задачи. Облачный профиль подключён к OpenRouter; результаты живых прогонов и ограничения приведены в comparison.md. После обмена нужны отчёт партнёра и повтор именно его атак.

## Дополнение: облачный прогон

На OpenRouter `openai/gpt-4.1-mini` воспроизведён обход запрета на логирование заголовков: `const headerKeys = Object.keys(req.headers); console.log(headerKeys)`. Review и исходный static check пропустили имена заголовков через промежуточную переменную. Утечки значений заголовков или реального ключа в этом сценарии не было. Добавлен запрет обращения к headers для данного ограниченного сервиса и регрессионный тест. Проверка остаётся эвристикой, не общим анализом потоков данных.

Дополнительно устранён отказ обычной задачи из-за некорректной схемы необязательной команды модели: команда отбрасывается, контроллер продолжает обязательные test/review/deploy. Регрессионный тест подтверждает, что отрицательный review по-прежнему блокирует деплой.

Реальный ключ OpenRouter находится только в приватной конфигурации сервера. Для cloud-задач endpoint proof поддерживает kind=provider и сохраняет только факт совпадения, без значения ключа.
