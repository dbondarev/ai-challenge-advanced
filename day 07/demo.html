Классификация ответа в LinkedIn-продажах: одно слово enum. Сначала eval с эталоном и два прогона базы (без system и с коротким промптом) — планка для тюна. Потом train/valid из прод-меток, формат как в дне 6. QLoRA на 1.5B эту планку проходит; на чужих проектах (eval2) промпт почти не работает.

Задача

Сервис: Nexus outreach, авторазметка входящих. Вход — тред до последнего IN. Выход — как этот ответ меняет статус (не накопленный статус треда).

System (одна строка на train, valid, eval):
How does the last IN message change the prospect's status in this LinkedIn sales thread? Reply with one word: no_change, rejection, not_ta, positive, mql, sql, meeting_held.

no_changerejectionnot_tapositivemqlsqlmeeting_held

Метрика: normalize(pred) in gold_key. Нормализация: lowercase, обрезка кавычек/точки, первое совпадение с regex. Temperature 0, max_new_tokens 8. Формат JSONL дня 6: system / user / assistant, ChatML, max_seq 512.

Разметка train/valid

  1. Старт: прод v2 на 710 inbound.
  2. Ручной аудит 130 строк: 44 поправили.
  3. Судья claude-opus-5-5 на всех 710 с правилами из task.md. На 130 аудита судья совпал с человеком в 102, v2 — в 86.
  4. Где v2 и судья совпали (359) — оставили. Где нет (221) — человек выбрал: судья 187, v2 16, третья метка 16, 2 выкинули.

Итого 349 из 708 строк смотрел человек; 359 — согласие двух моделей. Eval gold: 16 строк переписаны с накопленного статуса на изменение от последнего IN (eval-relabel.json).
