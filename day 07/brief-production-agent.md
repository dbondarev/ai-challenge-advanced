## 1. Задача

Узкая, повторяющаяся, с проверяемым результатом. Одна функция: один тип входа → один формат выхода.

Подходит: классификация тикета в фиксированный enum; SQL/фильтр по схеме; JSON с 3–5 полями; extract order-id + status.

Не подходит: «отвечай как саппорт», свободный чат, длинные эссе, «будь полезным».

В `data/task.md` зафиксируйте:

- формулировку задачи;
- `system` — **одна** строка на весь датасет (train, valid, eval);
- формат `assistant` (regex или JSON schema);
- метрику: exact-match после нормализации **или** совпадение `gold_key`;
- как нормализовать (регистр, кавычки, пробелы, JSON key order).

---

## 2. Формат строки (день 6)

JSONL, одна строка = один пример. Кодировка UTF-8. Переносы внутри полей — JSON `\n`.

```json
{"id":"tr-001","split":"train","kind":"happy_path","system":"<тот же system на все сплиты>","user":"...","assistant":"..."}
```

| Поле | Правило |
|------|---------|
| `id` | уникальный, префикс сплита: `tr-` / `va-` / `ev-` |
| `split` | `train` \| `valid` \| `eval` |
| `kind` | тип входа (нужен для гистограммы) |
| `system` | идентичен во всех строках |
| `user` | весь вход модели; без секретов |
| `assistant` | только gold, без «Конечно!», без markdown-fence, если формат это запрещает |
| `gold_key` | опционально, если метрика не по всему тексту |

Длина примера (system+user+assistant) должна влезать в ~400–500 токенов. Длиннее — режьте вход, не gold.

Eval — тот же schema, `"split":"eval"`.

---

## 3. Eval сначала, потом train

Порядок обязательный:

1. Собрать **eval** 40–80 эталонов. Их `user` больше никуда не копировать.
2. Прогнать `Qwen/Qwen2.5-1.5B-Instruct` (как день 6, temperature 0):
   - без `system` (пустой / нет system);
   - с вашим `system` из `task.md`.
3. Записать цифры в `data/baseline.md` — это планка для тюна.
4. Только после этого собирать train/valid.

Сплит: сначала отложить eval, остаток → train / valid (~10–15% valid). Пересечения по `id` и по нормализованному `user` быть не должно.

---

## 4. Обучающий набор

- Не меньше **200** строк в `train.jsonl`.
- Источник: уже существующие данные системы (логи, тикеты, переписки, документация, выгрузки). Не выдумывать домен.
- Чего не хватает: разметить руками **или** сгенерировать только `user`, а `assistant` — по правилам gold / человеком. Не генерировать gold «как модели вздумается» без проверки.
- Хотя бы **3** значения `kind`. Ни один `kind` не больше **60%** train.

---

## 5. Почистить

- Убрать полные дубли и почти-дубли (`user` после lower + collapse whitespace).
- 30 случайных train просмотреть глазами: неверный `assistant` → fix или drop. Список — `audit-30.json`.
- Все `assistant` проходят шаблон из `task.md`.
- Нет паролей, токенов, MFA, персональных данных, чужих клиентских тайн. Редактура или drop, не маскировка «***» внутри gold, если от этого ломается формат — лучше выкинуть пример.

## 8. Как прогнать baseline (если есть GPU / тот же venv дня 6)

Хост дня 6: `ssh nv307001`, venv `~/day06-qlora/.venv`, модель `Qwen/Qwen2.5-1.5B-Instruct`.

На каждый eval-пример два generate temperature 0: без system и с system. Скоринг — как в `task.md`. Если GPU недоступен — соберите eval/train и оставьте `baseline.md` с пометкой `blocked: no GPU`; цифры допишет агент тюна. Не подставляйте выдуманные scores.
